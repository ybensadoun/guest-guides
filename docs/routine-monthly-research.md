# Monthly research routine (Claude Code in Anthropic's cloud)

What the scheduled cloud routine "Monthly research for the guides" does, after the server's monthly run (`worker/monthly.mjs`, the 1st at 9:00 Madrid). It runs the 1st at 10:00 UTC (11:00 Madrid in winter, 12:00 in summer), on two checkouts: `ybensadoun/guest-guides` (this repo, public) and `ybensadoun/ca-la-kimberly-notes` (the private shared notes). Its cloud environment, `guide-research`, holds `SUPABASE_SERVICE_KEY` and `GOOGLE_PLACES_KEY` (full network access; no connectors attached on purpose: it reads unknown websites, so it must not reach email or Drive). Routine: claude.ai/code/routines/trig_018r2sTCgiEcLnH8VudrB28u, Opus 5.5. Later hardening: the environment's "Network secrets" (a proxy adds the key, the session never sees it) once the scripts can work without the key in their own headers. Plan: `docs/plan-worker-on-server.md`, "The monthly check in the cloud". It replaces steps 7 to 9 of the paused desktop task "Monthly check of every live guide".

## Instructions for the routine
You run once a month with no one watching. Work carefully, change little, and end with a short summary for Yohann (he reads it in the Claude app or as the pull request's description).

0. Find both checkouts. Read, in this order: the notes' `CLAUDE.md` and `PROJECTS.md` (section "Data accuracy"), then this repo's `CLAUDE.md`, `sites/ca-la-kimberly/CLAUDE.md`, `docs/CURATION.md` and `docs/TYPOGRAPHY.md`. Their rules apply, above all: no em-dashes in any language; all of a guide's languages in sync; never the house address; never tell guests to contact the hosts; "expected" for anything not confirmed; never print or commit a key; Wi-Fi never in git. The notes repo is read only for you: never commit there (put anything for CHANGES.md in your summary).
1. The report. Fetch the newest one (the key stays in the environment; never echo it):
   `curl -s "https://dmoxszfwulolqkgxtxcp.supabase.co/rest/v1/events?select=created_at,data&kind=eq.monthly_report&order=created_at.desc&limit=1" -H "apikey: $SUPABASE_SERVICE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_KEY"`
   `data.text` is the report, `data.date` its day. If there is none from this month, stop: say so in one line (the server's run did not happen or did not save; Yohann checks `journalctl -u guide-worker-monthly` on the server).
2. Lines for a human, every guide. In part 1 of the report these are the lines saying: no listing with this name near its pin; permanently or temporarily closed; official days that differ from Google's; Google lists hours but the guide has none; an error. In part 2, any automatic event that looks wrong (outside the area, a topic the host listed to skip, no real source). For each one, search the web for the official source (the venue, its operator, the town hall, the tourist office) or recent local press. Write one line: the place, what you found, the link and the source's date, and what should change. Never edit a host's guide (any guide but ca-la-kimberly): the host decides in the editor, so list them per guide for Yohann.
3. Ca La Kimberly only (`sites/ca-la-kimberly`, its live copy is the database):
   - `npm ci`, then `npm run guide:pull -- ca-la-kimberly`.
   - Record in `sites/ca-la-kimberly/docs/sources.json` the sources of the automatic events part 2 added to ca-la-kimberly (the "+" lines under it), with today's date.
   - Where a source confirms a fix for one of its lines (closed for good, wrong days, missing hours), make it in `sites/ca-la-kimberly/content` following PROJECTS.md "Data accuracy", and record source and date in `docs/sources.json`. Nothing else: no new places (the server queued Find more searches; Yohann reviews them in the editor), no wording changes.
   - Then `npm run check -- ca-la-kimberly` and `npm run build -- ca-la-kimberly`; the UX check: `npm i --no-save playwright && npx playwright install --with-deps chromium`, then `node engine/scripts/ux-check.mjs ca-la-kimberly` must print "UX check OK" (long words already listed in the notes' CHANGES.md may still show). If Chromium cannot be installed here, say so and do not push content.
   - Only if content changed and every check passed: `npm run guide:push -- ca-la-kimberly`. It refuses while the editor has unpublished changes: then say so and never use `--force` or `--drop-draft`.
4. Repo changes (sources.json, content files): commit them on a new branch and open a pull request on guest-guides, with your summary as its description. Never push to main (main goes live). Nothing changed: no pull request.
5. Google: only through the repo's scripts (`npm run check-places -- ca-la-kimberly` if you need it), never a loop of searches or page fetches on google.com, never a CAPTCHA.
6. Summary for Yohann, short: per guide, the lines for a human with what you found and the links; what you fixed in Ca La Kimberly and whether `guide:push` ran; what needs him; anything for CHANGES.md.
