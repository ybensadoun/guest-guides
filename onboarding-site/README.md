# Porta onboarding (public site)

Live at https://porta-guides.netlify.app (Netlify project `porta-guides`).

- `index.html` is the deployed page. Answers and photos stay in the visitor's browser (localStorage + IndexedDB) until they press Send.
- On Send it posts to Netlify Forms: `onboarding` (answers, device, walkthrough timings), one `file` submission per photo,
  `note` (the "Missing a question here?" notes, sent immediately), `feedback` (review rounds, `?feedback=<sid>&guide=<slug>`).
- Edit the sources in `src/` and rebuild: `cd src && python3 build.py` (writes `src/index.html`; copy it up one level).
- Deploy: Netlify (porta-guides) builds from GitHub (guest-guides, main, base directory onboarding-site). Test first, commit on main, the user clicks Push origin in GitHub Desktop. Anything pushed to main goes live. No dragging.

- Signed out (29 Oct 2026): the first page is in the guides' own look (Ca La Kimberly's paper, primaries, Jost, tiles with a corner shape): the promise, then the card that asks for the listing link (no account yet, step 7 below), then what guests get: Ca La Kimberly's home for an example house, Casa Sol, with the same pieces, shapes and sizes (welcome card; bins tonight, house guide, emergencies; local shop and pizza with open or closed, taxi and train, markets "7 today", places to eat, what to do, map; What's on: today's markets, the next 2 days, events coming up). All made up and static: only the visitor's clock picks the day, the bin and open or closed, so it looks live; nothing is looked up, and it shows nothing the guides cannot do (no live trains). `acToday`, `acExample` and `gate()` in `src/account.js`. "Continue with Google" shows only when Google is switched on in Supabase (`/auth/v1/settings`, `external.google`), so a half-set-up provider never shows a broken button. Google sends the visitor back to `/#access_token=...` like the email links; `render()` waits while the address carries a token. A brand-new Google account counts as a sign-up (notification), then the same start as an email account. Add a house from any account (Ca La Kimberly's included) gives that same start too; both are checked by `test/check.mjs`.
- The phone next to every step (from 1240 px wide, 29 Oct 2026, Yohann: "we should always see the preview"): in the builder it is drawn from the answers (`pvParts`, `phoneRender` in `src/preview.js`), in the layout the host picked, else Bauhaus ("Big colour tiles", as `generate-site.py` does); in the editor it is the guide itself, the shared viewer with the unpublished changes (`/g/<slug>?preview`, `cmPhoneOn` in `src/editor.js`), on the screen the step changes, reloaded after each saved change. Both draw the guide at 390 px and scale it into the frame (`phoneFit`), so text wraps as on a phone. Nothing loads on smaller screens, except on the builder's The look (below); the phone says so when it cannot show the guide (no web address, no connection), and the builder's caption says when it is only an example.
- Getting around (29 Oct 2026, Yohann: "the host only adds added-value data"): stations and stops are added with one field, their name or their Google Maps link (`cmStopAdd`: `/api/places?q=` finds the place, its pin and distance). The guide worker then looks up the lines and where they go (job `find-transport`, `cmLines`), shown first in the card with Refresh the lines; the host writes only "In a few words" and "What guests need to know"; everything found can still be changed by hand. Taxis stay typed by the host.
- The look > Colours (29 Oct 2026): the chosen source stays highlighted (`theme.colorsFrom`; none = the layout's own). Colours from the cover picture or the logo reach every layout: the presets keep their tile colours in their own tokens (`--med-*`, `--ru-*`, `--sf-*`, `--accent`), and `edLayoutVars` in `src/editor.js` writes those too, for all layouts at once, darkening the strong ones until white text stays readable. `engine/scripts/generate-site.py` (`layout_vars`) does the same for guides built with "From my cover picture".
- Deleting (29 Oct 2026): in the houses menu, a delete button on each house (`DELETE guides`, policy "owner deletes own guides"; a published one asks to type its web address) and "Delete my account" (RPC `delete_my_account`: events, houses and the account; type the email). Not while a guide is being built (trigger `guard_guide_delete`). Deleting the open house opens the next one, or a new one. Photos: the worker (`worker/sweep-photos.mjs`). Checked by `test/check.mjs`.
- Privacy page (29 Oct 2026): `privacy/index.html`, served at `/privacy/` (a real file, so the catch-all rewrite to `index.html` does not touch it), linked from the sign-up card and from Google's consent screen. - One editor (23 Oct 2026): once the guide exists (built, or imported like Ca La Kimberly), the same steps edit the guide itself instead of the answers (`src/editor.js`, hooked into `runtime.js` render and `nav.js`). Changes save to `guides.draft`; Preview opens `/g/<slug>?preview`; Publish changes copies the draft into `content`. Plan: `../docs/plan-single-editor.md`.

No host phone, first name or backup contact (Yohann, 30 Oct 2026). The taxi is in Only you know under Getting around, and is optional.
- The web address (30 Oct 2026, Yohann: "we can't expect the host to know it"): the database says whether an address is free (`slug_check`, for visitors too: other hosts' guides stay private) and offers up to three free ones near it, the town first, then numbers. An address the host did not type moves to the first of them by itself and says why (`slugAuto`, `slugAsk`); one they typed stays theirs: "Already taken", with the free ones to tap. Asked again just before Publish, because someone may have taken it meanwhile; the unique index keeps the last word. The field is on Review and send and in Name and languages. Reserved words are in the database (`slug_reserved`), not here. A draft holds its address until it is deleted.

The builder opens on the next step that needs the host; the editor on the step the host was on last time in that guide (this device, `porta-editor-step-v1`), else the first; `#home` opens that step too. The step list (rail on wide screens, "All steps" sheet on phones) starts with the guide's name. Publish, Preview and Unpublish are on the Publish step and in each step's footer. Check both without signing in: `node onboarding-site/test/check.mjs [editor slug] [builder slug]` (build first; screenshots in `onboarding-site/test/shots/`). Plan: `../docs/plan-fast-builder.md`.
- The wow (29 Oct 2026): the link opens "This is your guide" (`#yours`): a phone where the guide builds itself, the house photo and the listing's title as soon as `/api/listing` has read the page (`stage: "page"`, a few seconds), the sections when Claude is done (`stage: "write"` with the `src` the first stage returned, so the listing is read once; a call without `stage` still does both). The same phone sits next to every step from 1240 px wide and follows the step (`STEP_SCREEN`), live as the host types (`preview.js`: `pvParts`, `phoneRender`).

- Places nearby (29 Oct 2026, `../docs/plan-fast-builder.md` step 5): things to do only, one big card at a time from `/api/places` (`swipeInner`, `swDecide` in `src/start.js`): drag it right to recommend, left to skip (it follows the finger, `touch-action: pan-y` keeps the page scrolling), or the buttons, or the arrow keys; Undo; each yes lands in the phone with the host's comment. Bars and restaurants are never searched (Yohann: too much noise on Google Maps): the host types their own list in "Bars and restaurants", on the path right after (`FLOW` in `src/runtime.js`).
- Only you know (29 Oct 2026, `../docs/plan-fast-builder.md` step 6): Wi-Fi, arrival, rubbish and contacts are one step (`known`, `knownHTML` in `src/start.js`); the four modules stay in `MODULES` with `part: 'known'` for their fields and are left out of the step list (`visible()` in `src/runtime.js`), as is Your style (`off: true`). Each part is ticked once answered, the phone shows the part with the focus, and an old address (#wifi) opens the next step that needs the host.
- No account until the end (29 Oct 2026, `../docs/plan-fast-builder.md` step 7): the first page asks for the listing link, and the wow and every step work signed out; the answers and photos stay on the device (localStorage, IndexedDB) and the top bar offers Log in. The account is asked when it is needed: "Save my guide" on Review and send, or before an artistic cover (`acctNow` in `src/account.js`: the card alone over the builder, Google or email). Then the page starts again and the guide started on this device (`startedHere`: a link, a listing read, or step by step) becomes a house of its own in the account, never on top of one it has (`acctAttach`); Google comes back to the step the host was on (`porta-return`).
- Research of the area (29 Oct 2026, `../docs/plan-fast-builder.md` step 8), in two stages (`researchStart` in `src/start.js`): as soon as the listing page gives the house's position (before Claude writes) without an account, a quick search (`areaStart`: the database function `start_area_research`; the nearest markets and the emergency services); once the guide has an account (at once for a host who is signed in, and right after "Save my guide"), the full research in the background (`researchJob`: guide job `research`). `areaWatch` follows both (every 6 s for the first 3 minutes, then every 20 s) and the phone shows what comes back (Local markets, Things to do, Emergency and contacts), the full research first. Their ids travel with the answers (`_research`, `_researchJob`) and the build uses them. Limits and cost: `../worker/README.md`.
- Around you, named for the host (29 Oct 2026, Yohann: "it should be very clear what each section is requiring"): in the builder and the editor the steps are Attractions (museums, castles, theme parks, karting, nature; was Things to do), Eat and drink (was Bars and restaurants), Local markets, Local events and Nightlife, each saying what goes in it and what goes elsewhere. Guests keep the engine's tile names. Nightlife (late bars, clubs, live music) is optional: off in Guide sections (`SECTIONS` in `src/src.html`, `cmSections` in `src/editor.js`); switched on, its step follows Eat and drink in the builder (`favNight`, on the path) and Attractions in the editor, and in the editor its first place makes its section after Things to do (`cmNightEnsure`). `generate-site.py` writes `content/nightlife.json` from `favNight` like the restaurants, and the worker looks the places up on Google.
- Name: hosts see "Guest Guide Maker". "Porta" survives only in internal names (repo, Netlify project porta-guides, storage keys).
- Photos: the listing's photos (with Airbnb's own captions) are added to "Photos by room" with a guessed room, and the host confirms them. They are sent as links in the `listing_photos` form field; `engine/scripts/generate-site.py` downloads them into the right rooms.
- Step 1 is "Load your listing": it calls /api/listing (reads the page directly, or through the public reader r.jina.ai when Airbnb refuses servers; then falls back to pasted text), fills the next steps and adds the photos. /api/photorooms asks Claude to look at the photos and propose a room for each. "Guide sections" comes right after "About the place" and decides which question steps follow.
- "The look" (onboarding and editor, decided 28 Oct 2026): 1. logo (optional, none shown without one), 2. cover picture (one of the listing photos, an upload, drawn from the colours, or an artistic version of the chosen photo, made by the worker's `cover-art` job; the host sees it and keeps it or tries again), 3. layout, 4. colours (the layout's own, from the cover, from the logo). Fonts come with the layout; the editor has a folded "Fonts" list, each name in its own typeface. The style questions (words, inspiration images, apps they like, what to avoid, what first) are gone.
- The listing's full amenity list (`answers.listingAmenities`, up to 120) fills each room of the house guide with a line and a short text (guides made before 28 Oct 2026 do not have it).
- Reading the listing: no guessing. The function pulls the page's own data (overview, house rules section, amenities, sleeping arrangements, rating) and Claude only copies it; anything the page does not say stays empty. Only the tagline and welcome text are written by Claude (marked "Suggested by Claude").
- Optional section "Ratings and reviews" (off by default, one yes or no): the generator writes `content/reviews.json` {mode:"live", rating, count, source, url, quotes:[]}. Live, not curated: the guide shows the listing rating and latest reviews as they are. The engine does not show it yet (GUIDE builds that section).
- Listing data read from Airbnb's page data: the photo tour (rooms with their photos, so rooms are exact, not guessed), sleeping arrangements ("Bedroom 1: 1 king bed"), overview counts, house rules, amenities, rating. /api/listing returns a `report` (how it was read, what was found) that the Load step shows as a found / not found list. Via the page reader only the visible text is available, so sleeping arrangements and exact rooms are usually missing there.
- When the writing assistant (Claude) fails, /api/listing still returns what the page states exactly (counts, times, rules, sleeping arrangements, rating, photos with rooms) and `report.assistant = 'failed'` with the technical `code`; the Load step shows an orange warning with that code. If nothing could be read either, it returns an error message.
